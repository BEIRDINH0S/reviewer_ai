AI Reviewer

Un outil qui relit le code d'une pull request Java et signale les bugs potentiels.

Le principe

Envoyer un dépôt entier à un modèle de langage coûte cher et donne de mauvais résultats : le modèle se perd. Cet outil procède autrement. Il repère d'abord les méthodes modifiées entre deux commits, puis construit un graphe des appels entre méthodes, et n'envoie au modèle que la méthode modifiée accompagnée de ses voisines directes. Le contexte reste assez petit pour qu'un modèle local suffise.

Le parcours d'une analyse

  1. Le diff compare les deux commits et remonte jusqu'aux méthodes concernées.
  2. Le graphe indexe le dépôt : quelle méthode appelle quelle autre.
  3. Le contexte assemble, pour chaque méthode modifiée, son code et celui de ses voisines, sous un budget de tokens.
  4. Le modèle analyse ce contexte et renvoie une liste de problèmes.
  5. La vérification écarte ce qui n'est pas crédible.
  6. Le rapport met le reste en forme.

Par où commencer la lecture

  • com.reviewerai.model.MethodRef — l'identifiant qui circule entre toutes les briques.
  • com.reviewerai.service.DefaultReviewService — l'enchaînement complet, en une classe.
  • com.reviewerai.service.ReviewServiceFactory — le seul endroit où les implémentations concrètes sont choisies.

Une règle qui traverse le projet

Le code analysé n'est jamais exécuté : pas de compilation, pas de script de build, pas de téléchargement de dépendances. Il est lu, et rien de plus.
