AI Project Reviewer

Un outil qui évalue automatiquement un projet Java selon des critères notés, et produit un rapport LaTeX.

Le principe

Envoyer un projet entier à un modèle de langage est impossible : plusieurs centaines de fichiers face à une fenêtre de contexte de quelques milliers de jetons. Cet outil procède autrement. Chaque critère d'évaluation déclare les fichiers qui le concernent, et reçoit une sélection d'extraits choisie pour lui, sous un budget de jetons. Le contexte reste assez petit pour qu'un modèle local suffise.

Une partie des critères ne fait appel à aucun modèle : compter des fichiers de test est exact, gratuit et instantané, là où interroger un modèle serait lent, coûteux et faux de temps en temps. Les deux familles cohabitent derrière la même interface.

Le parcours d'une évaluation

  1. Le chargement importe le projet — répertoire, dépôt git ou archive — et classe ses fichiers.
  2. Chaque critère note le projet sur un aspect : architecture, lisibilité, sécurité, présence de tests…
  3. Le contexte choisit, pour chaque critère confié au modèle, les extraits à envoyer, sous un budget de jetons.
  4. Le modèle renvoie une note argumentée, avec réessai en cas de panne.
  5. La vérification écarte ce que le modèle a inventé — notamment tout signalement citant un fichier qu'on ne lui a pas montré.
  6. Le rapport met le résultat en forme, en LaTeX ou en Markdown.

Par où commencer la lecture

  • com.reviewerai.criteria.Criterion — le coeur du projet : ce que l'outil sait juger, et le point d'extension principal.
  • com.reviewerai.criteria.AbstractLlmCriterion — le déroulé commun aux critères confiés au modèle, fixé une fois pour toutes.
  • com.reviewerai.service.DefaultEvaluationService — l'enchaînement complet, en une classe.
  • com.reviewerai.service.EvaluationServiceFactory — le seul endroit, avec Main, où les implémentations concrètes sont choisies. C'est là que se lisent les réponses à « comment changer de modèle ? » et « comment ajouter un critère ? » : une ligne chacune.
  • com.reviewerai.model.EvaluationResult — ce que produit une évaluation, et tout ce dont le rapport a besoin.

Deux règles qui traversent le projet

Le projet évalué n'est jamais exécuté : pas de compilation, pas de script de construction, pas de téléchargement de dépendances. Il est lu, et rien de plus.

Ce que renvoie le modèle est une donnée non fiable, parce qu'il a lu du code qui peut contenir une injection de prompt. Sa réponse est validée, filtrée, puis échappée selon le format de sortie — et l'échappement LaTeX est une mesure de sécurité, pas de mise en forme : LaTeX est un langage exécutable dont le compilateur sait lire des fichiers.
